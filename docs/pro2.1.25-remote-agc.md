# Pro 2.1.25：远端识别副本 AGC（修复低声/音量偏小漏抓）

- 日期：2026-11-15
- 包：`net.user.callcaptionpro_1.0.0-pro2.1.25_arm64e.deb`
- 大小：6,521,992 字节
- SHA-256：`8f394d4fc1168ada11b65fd119c64a7ab59474efe59b2a00eeb483ca3b433cd7`
- 构建：GitHub Actions run `43714973685`，commit `699b813`
- 模型包：不变，继续 `models_1.0.1`

## 1. 为什么做

A 组短版 5 段测试里，第 5 段轻声男声**没有字幕**。

`remote16k.wav` 在 155–180 秒的 RMS：

```text
155s: 0.0043
160s: 0.0043
165s: 0.0002
170s: 0.0002
175s: 0.0012
180s: 0.0000
```

这段音频实际上能听见，但远端电平太低，x-asr 没抓住。  
PC 上把同一段做 0.06 目标 AGC 后，x-asr 能出：

```text
I'm speaking more likely
Chinese subtitles.
```

说明低电平是主因，AGC 方向有效。

## 2. 改了什么

`CCProASR.m` 的 `CCASRStream`：

- 只对 **远端流**（`_isLocal == NO`）做 AGC；
- 在 `flt` 送进 Sherpa 之前做，**不修改 `remote16k.wav`，也不影响播放原声**；
- 目标 RMS 0.06；
- 增益范围 1.0–24.0；
- attack 快（0.6），release 慢（0.25），避免忽大忽小；
- 数字静音时缓慢回落到 1.0；
- 峰值 clamp 到 ±1.0，避免削波；
- 日志：
  ```text
  R agc rms=0.0002 gain=20.5
  ```

每通电话 reset，不跨通话。

## 3. 不改变什么

- 不改 ASR 模型；
- 不改 TTS；
- 不改增量播报开关；
- 不改你听到的对方原声；
- 不改 `remote16k.wav` 原始文件，方便继续做电平分析。

## 4. 测试步骤

1. 安装 2.1.25，覆盖 2.1.24。
2. 设置保持：
   - 中文字幕语音播报：开；
   - LCT 式增量播报：开（A 组）；
   - 对方原音：30。
3. 用短版 5 段，同音量/位置/顺序播放。
4. 重点看第 5 段：
   - 是否出字幕；
   - `asr.log` 是否出现 `R agc rms=... gain=...`，第 5 段 gain 是否升到 15–24；
   - `R final` 是否出现 `I am speaking more quietly now` / `hear me clearly`。
5. 再关增量开关测 B 组；AGC 两组都会生效。

## 5. 失败分支

- 第 5 段仍无字幕，且 `R agc` gain 已到 24：
  - 说明 24 倍还不够，或这段音频被系统降噪/静音；
  - 发 `remote16k.wav` + `asr.log`，再评估目标/上限。
- 第 5 段有字幕，但噪声段出现更多假字幕：
  - 说明 AGC 放大了环境噪声；
  - 需要加噪声门/语音活动判断，而不是继续加增益。
- 正常段音量被放大到削波：
  - 看 `R agc` gain 是否长期 >1；正常语音应回落到 1 左右。
