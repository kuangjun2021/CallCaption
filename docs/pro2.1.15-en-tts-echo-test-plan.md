# Pro 2.1.15 英文 TTS 上行回声测试方案

- 目标：验证“对方听着英文 TTS 同时说话”时，英文 TTS 是否会被对方麦克风收进去，进而污染远端 ASR。
- 版本：`pro2.1.15`，测试期间不要换包。
- 关键设置：`AsrTTSMute=0`（保持关闭）。

## 1. 先分清两条路径

| 路径 | TTS 方向 | 谁听得到 | 影响谁 | 需要切换哪台手机 |
|---|---|---|---|---|
| 英文 TTS 上行回声 | 本机中文 → 英文 TTS → 上行 | 对方 | 远端 ASR（对方麦克风收进 TTS） | **对方手机** 听筒/免提/耳机 |
| 中文 TTS 下行回声 | 对方英文 → 中文 TTS → 下行 | 本机 | 本地 ASR（本机麦克风收进 TTS） | **本机手机** 听筒/免提 |

所以“听筒/免提”要分开测：对方手机的模式测英文 TTS 回声，本机手机的模式测中文 TTS 回声。

## 1.5 单人双机测试法（推荐）

两部手机放在同一张桌子上会形成双向耦合：Phone A 的扬声器被 Phone B 的麦克风收进去，Phone B 的扬声器又被 Phone A 的麦克风收进去。这样测到的“回声”是近距离人为放大的，不能代表真实通话。A 这通的中文碎片和弱 TTS 相关峰，很可能就是这种耦合造成的。

推荐把“对方”拆成两部分：

- Phone B（对方手机）放在**另一个房间**，或者放进垫了毯子的纸箱里，和 Phone A 隔开；
- 在 Phone B 麦克风旁边放一个**外接音箱/笔记本电脑**，播放一段**已知文本的连续英文**，模拟对方在说话；
- Phone B 的听筒/免提播放 Phone A 上行的英文 TTS；
- Phone B 的麦克风同时收：外接音箱的英文 + 自己听筒/免提漏出来的 TTS；
- Phone A 在另一个房间，只收本机用户的中文，不直接听到 Phone B 的外接音箱。

```text
房间 A                         房间 B
Phone A (本机)  <-- WhatsApp -->  Phone B (对方模拟)
用户说中文                      外接音箱播放已知英文段落
                                 Phone B 听筒/免提播放英文 TTS
                                 Phone B 麦克风收：已知英文 + TTS 回声
```

没有第二个房间时：

- 用纸箱 + 毯子/吸音棉把 Phone B 和外接音箱罩起来；
- Phone A 离箱子至少 3–5 米；
- 外接音箱播 3–5 分钟的循环音频，先开始播放，再走到 Phone A 拨号；时间足够。

外接音频要求：

- 已知文本、连续、无长静音，2–5 分钟循环；
- 用 PC/第三台手机播放，音量调到 Phone B 麦克风能清楚收到；
- 先做无 TTS 基线，确认远端 ASR 能转出这段英文；
- 不要用 Phone B 自己的扬声器播放“对方”的话，否则会和 TTS 走同一条路，分不清。

测试步骤（每个模式）：

1. 连好 WhatsApp 通话；
2. 先放外接英文，不说话、不触发 TTS，确认远端 ASR 能转出基线文本；
3. 本机说**一句**长中文，触发一条 5–10 秒英文 TTS，然后保持安静；
4. 对方（外接音箱）持续说话，TTS 播放期间自然形成重叠；
5. 重复 2–3 次，或让外接音频一直循环；
6. 挂断，导出日志和 `cc_tts.wav`（每次只做一条 TTS，避免参考被覆盖）。

这样你一个人就能测：外接音箱扮演“对方”，你只需要在 Phone A 说中文触发 TTS。

## 2. 测试矩阵

| 编号 | 对方手机 | 对方音量 | 本机 | 目的 |
|---|---|---|---|---|
| A | 听筒 | 中等 | 听筒 | 英文 TTS 上行回声基线 |
| B | 免提 | 中等 | 听筒 | 声学耦合增强 |
| C | 免提 | 最大，手机放桌上 | 听筒 | 最坏情况，AEC 压力测试 |
| D | 耳机 | 中等 | 听筒 | 对照组，理论上无回声 |
| E | 听筒 | 中等 | 免提 | 中文 TTS 被本机麦克风收进去（本地 ASR） |
| F | 免提 | 最大 | 免提 | 双向最坏情况 |

优先做 A、B、C、D；E/F 第二轮再做。

## 3. A–D 怎么演

1. 本机说一段长中文（生成 5–10 秒英文 TTS）：
   > 这是一段比较长的中文，用来生成一段足够长的英文语音，测试对方在英文翻译播放的时候说话会不会被回声干扰。
2. 本机说完后保持安静，不要抢话。
3. 对方听到英文 TTS 开始后，立刻用英文连续说一段**新内容**：
   > The quick brown fox jumps over the lazy dog while the translation audio is still playing, and I am deliberately speaking a sentence the recognizer has never seen before.
4. 对方说完就停，本机直接挂断。
5. 每个模式重复 2–3 次，记录：对方手机型号、听筒/免提/耳机、音量、手机是否放桌上、环境是否安静。

注意：

- 每次通话只做**一条**长英文 TTS，挂断前不要再触发新的英文 TTS，否则 `cc_tts.wav` 会被覆盖。
- 本机在英文 TTS 期间必须安静，否则远端 WAV 里会混入本机声音，影响判断。
- 对方必须**在 TTS 播放期间**说，不是等 TTS 结束再说。

## 4. E/F 怎么演

1. 对方说一段长英文，触发 5 秒以上中文 TTS。
2. 第一轮：本机保持安静，看本地 ASR 会不会把中文 TTS 识别成字幕。
3. 第二轮：本机在中文 TTS 播放时说自己的一段中文，看本地 final 是否完整、有没有 TTS 文字混进来。

## 5. 每次导出什么

每次通话后，把以下文件复制到单独目录（例如 `测试日志/1.0.0-pro2.1.15/en-echo-A1/`），避免下一通覆盖：

- `probe.log`
- `asr.log`
- `spool.txt`
- `remote16k.wav`
- `local16k.wav`
- `daemon.heartbeat`
- `cc_tts.wav`（英文 TTS 参考）
- 中文 TTS 测试时加 `cc_tts_zh_000N.wav`

## 6. 分析判据

### 6.1 识别层

- 对方说话期间，remote final 是否完整；
- 有没有出现英文 TTS 的原文或残缺词；
- 本机说话期间，local final 是否完整，有没有中文 TTS 原文。

### 6.2 信号层

用 `tools/analyze_tts_echo.py` 把 TTS 参考音频和麦克风 WAV 做归一化互相关：

```bash
python tools/analyze_tts_echo.py --tts cc_tts.wav --mic remote16k.wav
```

- `corr`：归一化相关系数，越高说明 TTS 残留越明显；
- `gain`：回声路径增益；
- `erl`：回声返回损耗，越负说明残留越小（例如 -20 dB 表示回声比参考低 20 dB）。

中文 TTS 本地回声换参考文件：

```bash
python tools/analyze_tts_echo.py --tts cc_tts_zh_0001.wav --mic local16k.wav
```

### 6.3 预分析结果（2.1.15 现有数据，仅供参考）

用最近一通的 `cc_tts.wav` 与 `remote16k.wav` 做预分析：

- 最强相关峰 `corr ≈ 0.093`、`gain ≈ -0.098`、`ERL ≈ -20.2 dB`；
- 峰值分散在 0.88s / 11.61s / 13.75s / 21.94s / 24.22s，没有出现与 TTS 播放位置对应的单一强峰；
- 同一条英文 TTS 对 `local16k.wav` 也没有明显峰（对照组，符合预期）。

说明这通电话里英文 TTS 在远端 WAV 中的残留很弱，但对方手机当时的听筒/免提和音量未知，不能替代 A–D 的受控测试。

## 7. 结论怎么定

- A–D 中，如果 C（对方免提最大音量）仍然没有明显相关峰、远端 ASR 也没有 TTS 原文/缺词，说明对方手机 AEC + 声学耦合足够，当前架构可以不开关 AEC。
- 如果 C 出现明显峰或远端 ASR 被 TTS 污染，再决定是否在我们侧加 AEC/参考信号消除。
- E/F 单独判断本机中文 TTS 是否被本机麦克风收进去；这属于本地 ASR 回声，不要和英文 TTS 上行回声混在一起。
